# OMEGA APEX v1.3 — SECURITY & FAILURE-MODE REPORT
**Date:** `2026-11-13`  
**Scope:** Full remediation audit of v1.2 defects and v1.3 enforcement boundaries.

## 1. Remediated Vulnerabilities (Verified by Adversarial Tests)

| Vulnerability ID | Defect in Previous (v1.2) Codebase | Remediation Implemented in v1.3 | Regression Test Coverage |
| :--- | :--- | :--- | :--- |
| **`VULN-01` (`CRITICAL`)** | `.bin/omega-ticket` executed `success_check` via `subprocess.run(..., shell=True)`, allowing arbitrary command injection if a ticket JSON contained shell metacharacters. | Removed all `shell=True` calls across the entire repository. Replaced string checks with `TypedCheckSpec` (`file_exists`, `file_sha256`, `json_valid`, `yaml_valid`, `config_key_equals`, `test_result_present`, `allowlisted_readonly_validator` with `shell=False`) and regex metacharacter rejection (`[;|&$\`><\n\r]`). | `C08_command_injection`, `C09_shell_metacharacter_handling` |
| **`VULN-02` (`CRITICAL`)** | `.bin/omega-policy`, `.bin/omega-ticket`, and `omega-autopilot.py` accepted CLI flags (`--human-approved`, `--approve`, `--operator-confirm RATIFY_OR_APPROVE`) that any agent with bash access could pass to self-approve consequential actions. | Removed all CLI approval flags and deleted `omega-autopilot.py --apply`. `.bin/omega-policy` scans raw `sys.argv` and immediately rejects `--human-approved`, `--approve`, `--operator-confirm`, or `RATIFY_OR_APPROVE` with `DENY_SPOOF_ATTEMPT`. Consequential actions fail closed (`DENY_FAIL_CLOSED_NO_HOST_APPROVAL_CHANNEL`) when `/run/omega_operator_oob.key` is absent. | `C04_policy_enforcement`, `C05_approval_spoofing_attempts`, `C10_approval_expiry_and_replay` |
| **`VULN-03` (`HIGH`)** | `cordis.patch.yml` line 73 appended an unquoted `@deepseek-ai/dsh-tool-subagent:` mapping key to a top-level YAML list, breaking strict YAML parsers (`ScannerError`). | Rewrote `config/cordis.patch.yml` as a strict top-level YAML sequence (`list` of `- id:` objects) matching DSH-Go `0.2.2-rc.1`'s schema, placing `tool-subagent` (`modelDiscovery: false`) inside `preset-standard` -> `delegation` and setting `defaultPreset: read-only`. | `C01_config_parsing`, `C03_dsh_integration_compatibility` |
| **`VULN-04` (`MEDIUM`)** | Active tickets and missions could have their `objective` or `success_check` rewritten in place on disk without detection, and unverified claims could be repeated to appear established. | Added `immutable_contract_sha256` on tickets (`TICKET_TAMPER_DETECTED`), `objective_sha256` on missions (`MISSION_OBJECTIVE_TAMPER_DETECTED`), anti-repetition lock in `.bin/omega-memory`, and `verifier_actor != author_actor` enforcement. | `C07_ticket_tampering`, `C11_mission_state_integrity`, `C12_memory_provenance`, `C13_independent_verification` |
