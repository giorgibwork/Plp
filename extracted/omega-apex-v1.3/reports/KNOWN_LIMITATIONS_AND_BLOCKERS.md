1. **`BLK-HOST-01` — Token Harbor (`mimo-v2.6-flash:free`, `deepseek-v4.1-flash:free`) Requires Local API Key & Live Probe:**
   - **Verified Facts:** Token Harbor's official OpenAI-compatible endpoint is `https://tokenharbor.ai/v1` and serves both [`mimo-v2.6-flash:free`](https://tokenharbor.ai/models/mimo-v2.6-flash:free) and [`deepseek-v4.1-flash:free`](https://tokenharbor.ai/models/deepseek-v4.1-flash:free) at $0.00 ([Token Harbor Free APIs](https://tokenharbor.ai/blog/3-best-free-ai-apis-for-coding-and-agents-in-2026)).
   - **What Is Missing:** Token Harbor requires a user-generated `TOKENHARBOR_API_KEY` (`thk_...`) configured in `/root/.dsh/.credentials.yaml` or the host environment. Because this repair ran in an isolated sandbox without your private Token Harbor key, live inference on `https://tokenharbor.ai/v1` has not been executed and the provider is marked `BLOCKED` in `config/provider_integrations.json` until you add your key locally.
2. **`BLK-HOST-02` — DSH-Go `0.2.2-rc.1` Lacks an Out-of-Band Cryptographic Approval Socket for Subprocesses:**
   - **Verified Facts:** DSH-Go's `@deepseek-ai/dsh-permission-presets` (`approval: ask`) prompts the operator in the Web UI before launching a tool call (`tool-bash` or `tool-fs`), but does not pass a cryptographically signed per-operation token into Python subprocesses running inside PRoot.
   - **Fail-Closed Mitigation Applied:** `.bin/omega-policy` fails closed (`DENY_FAIL_CLOSED_NO_HOST_APPROVAL_CHANNEL`) on all `OP_CONSEQUENTIAL_EXEC` requests unless an external operator key (`/run/omega_operator_oob.key`, outside workspace write scope) signs the exact `proposal_digest`, `expires_at`, and single-use `nonce`.
